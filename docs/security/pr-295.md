# Review of upstream PR #295

Reviewed the original upstream PR #295 at `271d1111e3f3720fd04159d2c44bed8a335a9d71`, including all ten changed files and the receiving worker prompt/kill paths in this fork. This is a source review and targeted testing of the adaptation, not a security certification of the whole application.

## Findings in the upstream version

1. **High: bulk prompt dispatch targets shells and approval prompts.** Both the sidebar and monitor modal send `worker.prompt` to every worker. This existing channel pastes into a live terminal and submits Enter: in a shell, instructions become commands; in an agent awaiting approval, input can interfere with the question. There is no recipient review or state guard at dispatch.
2. **Medium: auto-assign accepts unsuitable sessions.** The selector accepts idle/done shells, helpers and missing worktrees. Its fallback also includes starting, offline and exited sessions. It can interfere with helper/meeting tasks or fail silently.
3. **Medium: send-home bypasses worktree decisions.** Raw `worker.kill` calls skip the existing inspection and keep/delete choices, and omit meeting/shared-session warnings. The server still protects detected uncommitted/unpushed work, but defaults can remove clean worktrees and branches; this is not an arbitrary filesystem deletion primitive.
4. **Medium, conditional on the report reader: exported Markdown trusts worker fields.** Names, provider fields and PR links are inserted without comprehensive escaping or URL validation. HTML or unsafe links can reach a downstream Markdown reader; impact depends on that reader's sanitization. Task metadata can also contain private information.
5. **Other compatibility/resource issues:** Minesweeper is replaced; UI logic is duplicated between two views; fallback audio creates unclosed AudioContexts outside the existing mute bus; worker colour is interpolated into CSS without validation.

The changed files add no dependencies, installation scripts, server endpoints, external fetches or telemetry. UI text uses DOM text nodes and canvas rather than HTML injection. Existing WebSocket authentication and same-origin checks still apply. The “Boss” label grants no new role or permissions; the office already exposes shared worker controls to signed-in users.

## Adaptation

- One feature module provides the dashboard, live monitor, per-worker terminals/helper reports, reviewed broadcast/auto-assign, individual send-home and a local report download.
- Shells, helpers, meeting/board agents, approvals, missing worktrees and starting/sleeping sessions are excluded from dispatch. Auto-assign selects only idle/done regular agents.
- Recipient names and prompt are reviewed before sending. Recipients are snapshotted, capped at 50, bound to the current floor and rechecked; newly hired workers never join an already reviewed broadcast.
- Guard metadata is verified at the WebSocket boundary and again immediately before the local or hosted session receives input. Older hosts that do not advertise guard support refuse Boss prompts; their existing controls remain available. A delayed Enter is suppressed if the session changes to an approval or another status. Prompts are capped at 2,000 characters and terminal control bytes are rejected. The existing generic prompt channel is unchanged for other callers.
- Individual send-home reuses the existing worktree/meeting confirmation flow. Bulk shutdown is omitted.
- Report text is escaped, unsafe/credential-bearing URLs are rejected, and raw full prompts/terminal output are not exported. Reports stay local until the user chooses to share them; activity metadata can still be private.
- Minesweeper remains available from the dashboard. Chimes use the existing muted alerts bus. Worker dots accept only six-digit hex colours.

Guarded bulk prompting does not establish a new authorization boundary for the office. The existing authenticated shared-control model remains in place. Busy agent prompts can still queue, and the dashboard reports requests rather than claiming delivery or execution.
