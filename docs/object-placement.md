# Renovation mode

Open **Menu → Renovation mode** on an office floor. Choose from the **Object** list, or click/tap furniture in the room; its gold outline marks the selection. Drag to move it across its horizontal plane. Rotate and Scale turn horizontal drags into smooth adjustments; numeric fields provide precision, with optional 15° rotation snapping. Uniform size ranges from 0.25× to 3×. Reset rotation, Original size and Reset Transform restore defaults. Confirm / Deselect keeps changes and releases the selection. Close with ✕ or Esc to resume gameplay.

Complete object bounds stay inside the office and below the ceiling; red feedback means the attempted change was rejected. Objects may overlap intentionally. Dragging preserves the current height and grab offset. **X**, **Height** and **Z** fields also allow precise positioning; Height is the vertical offset of a fixture assembly from its original floor. Keep the complete assembly below the ceiling. Mouse and touch use the same pointer controls. Other windows block scene selection.

In **3D**, walking stays active while the editor is open: use WASD or the arrow keys to reposition the player, including during an object drag. Hold the right mouse button and drag to look around in first person or orbit in third person; left-drag selects and edits objects. The cursor stays free for selecting objects and using the panel. While dragging in Move mode, the object follows the cursor as the player/camera moves. Numeric inputs pause held movement when focused, and other windows pause navigation until closed. **Walk through furniture while renovating** is on by default: editable furniture does not block your player while the editor is open. Switch it off to check normal collisions. This is a local editing aid, so other players keep their normal collisions. Closing the editor always restores collisions; walls, floors, stairs and other fixed structures retain theirs throughout. The 2D editor retains its stationary overhead view. Closing the editor restores normal mouse-look.

Each opted-in object has a stable ID, position, Euler rotation and scale. The office server owns the shared layout and broadcasts previews during dragging, rotating and scaling to every player on that floor in both 3D and 2D, even when their editor is closed. Previews are sent at most every 40 ms; completed adjustments flush immediately. The panel shows **saved to shared office** only after the server has written the layout to disk. A player joining, reloading, reconnecting or switching floors receives the authoritative snapshot. If two players edit the same object, the server's last accepted update wins. Different objects and floors remain independent.

Layouts live in the office's `.agent-office/placements/<hex-floor-id>.json`, including hosted floors, so they do not depend on a member's remote checkout. Atomic replacement protects the previous file during writes. Long drags are checkpointed every 300 ms; completed gestures, disconnects, floor departure and normal office shutdown flush pending server changes. Failed disk writes retain dirty data for retry and notify the editor. Editing requires an office connection; an interrupted pending edit is retried on reconnect. The current editable scenery belongs to the `office` map; another map neither receives nor alters it.

Browser localStorage remains a cache. Old personal placements are imported only for objects missing from the server's layout, so an old browser cannot overwrite an existing shared placement. Invalid records and protected IDs are ignored. Clearing browser data does not remove the shared layout. Back up the office's `placements` directory with its other `.agent-office` data.

The editable set includes the main office desks, agent kiosks, lounge couch/poufs, coffee table, rugs, ordinary plants, wall boards with their headings, lounge TV, machine monitor, kitchen assembly, bookshelves, knowledge shelf, arcade cabinet and ceiling lamps. Desks move as assemblies, carrying their chairs, toys, laptop/worker anchors and finishes. Interaction points, seat definitions, positional kitchen/arcade sounds, and collision bounds follow transforms. Worker walking routes use the current furniture collision layout. The kitchen moves as one assembly.

Walls, floors, doors, stairs, elevator, balcony/roof/garage furniture, meeting furniture, overflow/wing desks, activity fixtures such as the gong and sports tables, jukebox, animated free-moving props and plants managed by wing expansion remain protected. Jukebox placement keeps its existing dedicated controls. Objects may intentionally overlap other furniture; walk-through mode allows navigation during the edit. Existing interactions work normally outside renovation mode. Add safe scenery with `editable(object, stableId, label, collider?)` from `features/object-placement/model.ts` and its default transform in the shared `PLACEMENT_DEFAULTS` allowlist; another map needs a matching server namespace before opting in. Objects with externally managed anchors or simulations need an adapter first. Collider bounds follow transforms. Server validation protects IDs, the active floor/map, bounded height, supported rotation and uniform scale limits. The feature installs through client, fixture, message, snapshot, state-slice and lifecycle registries, and uses the existing modal/focus system. Renovation adapters live in `client/features/renovation/`, wrap explicit fixture slots from `shared/renovation.ts`, and add tools through the object editor extension registry. Existing scenery keeps its IDs and layouts. Versioned fixture slot IDs are server allowlisted; preserve their order and bump the namespace before incompatible changes.

Verify with `npm run typecheck`, `npm test`, `npm run build` and `node --import tsx scripts/e2e-renovation.mjs` (screenshots and checks in `/tmp/agent-office-renovation-evidence`). The existing scenery regression harness is `node --import tsx scripts/e2e-object-placement.mjs`.
